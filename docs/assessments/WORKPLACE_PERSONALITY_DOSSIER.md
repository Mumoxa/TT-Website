# Workplace Personality Profile dossier — draft implementation

**Status:** implemented for review, not approved for live assessment, invitations, reports or hiring use. Keep the existing launch gate and release controls in place. The report is a description of self-reported responses, not evidence of validation, job fit or professional certification.

## Design and data flow

The existing assessment admin's authenticated report endpoint retrieves the original encrypted result for the selected attempt. The UI builds the `tt-wpp-report-data-1` projection in `src/assessments/personality-report-model.js`, then renders `PersonalityDossier.jsx`. Browser printing (`window.print()`) is the existing PDF path; no new public endpoint, PDF engine, external API or model is introduced. The dossier does not use candidate contact, identity number, transport or availability details. The existing admin API still returns its established broader recruiter payload; it is not a newly minimized API. It uses `Cache-Control: no-store, private` and audits report viewing without answer content. The report toolbar is omitted from print.

The renderer consumes stored means, not item answers. Each complete factor must have ten answers and a finite mean in [1,5]. Zero-answer, missing or partial factors have no plotted score or directional interpretation; partial stored means are withheld. Duplicate, malformed or inconsistent completion and out-of-range values fail closed. Marker position is `(mean - 1) / 4`. Scores remain means, not percentiles. No scorer, assessment items or candidate flow was changed. The IPIP scoring source is https://ipip.ori.org/newBigFive5broadKey.htm and https://ipip.ori.org/newScoringInstructions.htm; the existing implementation expresses the keyed totals as item means.

Interpretation version `tt-wpp-interpretation-1.0.0-draft` is deterministic. Midpoint tolerance is ±0.1 (inclusive); the slight-lean language applies outside that interval and within 0.5 points of 3. These are editorial aids, not validated classifications or cutoffs. Questions vary by response direction and ask for independent examples; missing dimensions receive neutral questions. Their utility and fairness have not been validated. Use standardised, job-relevant questions and professional oversight for any future recruitment process. Neither end of a spectrum is presented as better.

The record prints UTC submission time, attempt number, recorded form, assessment and scoring versions and the current interpretation and template versions (`tt-wpp-dossier-1.0.0-draft`). Missing versions are labelled not recorded rather than inferred. The original attempt ID is retained in the in-memory model and the authenticated route, but not printed. Re-rendering is deterministic for the same input and code; there is **no immutable stored PDF or automatic retrieval of historical template versions**. Preserve the approved code revision and authorized PDF securely if exact historical reproduction is required; assess retention and consent policy first. Timestamp plus name and attempt number support human traceability but are not a globally unique identifier.

## Printing and privacy

Use the private recruiter result screen, select the personality attempt and choose Print / Save PDF, A4 portrait, background graphics enabled, default scale and no browser headers/footers. Check the four-page preview before saving, especially long names and local fonts. Store and share real exports only in approved private systems; browser printing or downloaded files are outside server cache controls. No real report or exported personal data belongs in Git, public assets, logs or the sample harness.

The sample harness is dev-only and uses fabricated data, including deliberately fake private fields. It is not a production route. The checked-in examples under `deliverables/personality-report/` are synthetic. To regenerate them, start Vite (`npm run dev -- --host 127.0.0.1`) and run `CHROMIUM_PATH=/path/to/chromium node scripts/render-personality-samples.mjs`. An installed compatible Chromium with required shared libraries is needed. The script uses existing Playwright and pdfjs-dist dependencies. `PREVIEW_BASE` and `REPORT_OUTPUT` override defaults. The script prints synthetic samples only and does not fetch real reports.

## Known limits / release blockers

- No psychologist, scientific, fairness, legal, POPIA, consent, accessibility or selection-validity approval is implied. An independent qualified review and explicit release authorization remain necessary. No live invitations, reports or selection use before approval.
- Latin (including accented), Greek and Cyrillic names were exercised; other scripts, bidirectional names and fonts depend on the browser/OS and are not certified. Accessibility, screen-reader output, physical print, alternate browsers, different print settings and uncommon or legacy data need human checks.
- Fixed A4 pages and smaller methodology text require inspection on actual printers. The longest synthetic name tested is within the existing 100-character per-name limit, but unusual glyphs or atypical version strings may change layout.
- Local synthetic tests and source inspection do not prove production configuration, deployment security, authorization policy, consent or secure storage. The implementation makes no deployment or validity claim.
